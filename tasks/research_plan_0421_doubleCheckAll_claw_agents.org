** Current OpenClaw situation

+ The original OpenClaw default profile was invalid and could not be trusted for evaluation.
+ An isolated profile =~/.openclaw-mobius-eval/= was created and brought to a valid state.
+ Gateway mode, gateway auth, and per-agent OpenRouter auth were configured for this isolated profile.
+ After these fixes, the old error =No API key found for provider "openrouter"= was removed.
+ However, OpenClaw still finishes each turn with:
   + empty payloads,
   + zero token usage,
   + =stopReason: "stop"=,
   + =replayInvalid: true=,
   + =livenessState: "abandoned"=.
+ Therefore, the remaining OpenClaw problem is no longer a simple calling-interface/configuration issue in our wrapper.
+ The remaining blocker appears to be an upstream/runtime regression in the installed OpenClaw build when handling model output.

** Practical conclusion for the current research stage

+ Hermes, ZeroClaw, and Nanobot are now in a usable state for the current evaluation workflow.
+ OpenClaw should currently be treated as =runtime-broken= for this experiment setup, rather than as a valid negative result for injection resistance.
+ In other words, OpenClaw's current failure cannot yet be interpreted as "the attack failed"; it is more accurately "the runner/runtime failed before producing a trustworthy experimental result".

** Recommended next step for OpenClaw

+ The next repair step is likely one of the following:
   + upgrade or downgrade the OpenClaw version inside the container,
   + patch the OpenClaw runtime in the container,
   + or add a response-normalizing proxy/workaround if the issue is caused by streamed provider fields.
